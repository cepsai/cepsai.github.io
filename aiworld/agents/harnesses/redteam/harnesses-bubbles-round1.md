# Red-team report: harnesses-bubbles.html

Checked 2026-09-02 against the GitHub REST API (all 35 repos re-fetched via `gh api`), the live `globalRankingMap` payload at https://openrouter.ai/apps (200 public rows, 30-day window), and vendor / press pages. Stars and OpenRouter tokens all match the inline DATA to within a handful of stars. The problems are in framing, classification and two chart-logic bugs.

## Findings

1. **blocker. The 85% headline depends on one non-coding agent.** Recomputed from DATA: 26 of 39 open (correct), open tokens 88.83T of 104.46T = 85.0% (arithmetic correct). But Hermes Agent alone is 49.2T, 47% of the total. Drop Hermes and the open share falls to 72% (39.6T of 55.2T). Drop Hermes and OpenClaw, both of which the sources file itself calls "not a pure coding harness" and "borderline", and it falls to 69% (35.0T of 50.7T). OpenRouter tags Hermes as `personal-agent, cli-agent` (https://openrouter.ai/apps). Fix: either (a) drop Hermes Agent and OpenClaw from the callout denominator and say "26 of 37 coding harnesses ... 69%", or (b) keep them but change the callout to "Open harnesses carry 85% ... (69% without the two general-purpose agents Hermes and OpenClaw)". Also add "general-purpose agent" to their tooltip type field so a reader sees why they are there.

2. **blocker. Warp is coloured "source code published" but its agent harness runs on Warp's servers.** Warp docs: with BYOK "your local Warp client ... sends it to Warp's backend along with your prompt, where the Warp Agent harness assembles the full request" (https://docs.warp.dev/agent-platform/inference/bring-your-own-api-key/). Only the terminal client is AGPL-3.0; the agent loop, Oz and the cloud are proprietary (https://www.helpnetsecurity.com/2026/04/30/warp-open-source-client/, https://thenewstack.io/warp-open-source-client/). In a chart titled "the harness layer is open", a 64,725-star blue bubble for a closed harness is the single most attackable point. Fix: set `open:false`, license "AGPL-3.0 client / proprietary agent", and add a tooltip note "Client is open; the agent harness runs on Warp's servers." Alternatively add a third colour "client open, agent closed" and use it for Warp.

3. **should-fix. Droid (14 stars) is drawn below the "no repo" row, off the axis.** `y = d3.scaleLog().domain([200, 600000])` and `cy = d.stars ? y(d.stars) : noRepoY`. 14 is 1.15 decades under the domain floor, so its dot lands ~0.33 * innerHeight below the x-axis, under the "no repo" row and possibly under the axis label. Fix: clamp, e.g. `cy: d.stars ? y(Math.max(d.stars, 200)) : noRepoY`, or set Droid `stars:null` and note "docs-only repo, 15 stars" in the tooltip. Same guard protects Auggie (276) and Junie (422), which sit almost on the axis line.

4. **should-fix. Command Code is in the "no repo" row but has a public repo with 3,865 stars.** https://api.github.com/repos/CommandCodeAI/command-code: `stargazers_count` 3865, README-only, `created_at` 2017-12-20 (a renamed repo that inherited its star history, pushed 2026-08-15). The sources file admits "stars not fetched". Trae (916, README-only) is plotted with stars, so Command Code is treated inconsistently. Fix: set `stars:3865`, keep `open:false`, tooltip gets the "(issues-only repo)" flag automatically. Add a note "repo dates from 2017 and was renamed; star count inherited."

5. **should-fix. Zazen (Freebuff fork), 8.25T tokens, rank 7, is missing.** It would be the 4th-largest bubble in the chart (https://openrouter.ai/apps, row "Zazen (Freebuff fork)", origin https://freebuff.com/). The sources file records it under Codebuff but the chart does not include it, so Codebuff shows 159B when its code base routes 8.4T. ZCode (Z.ai, rank 19, 1.29T, launched July 2026, https://zcode.z.ai/en) is also absent and is a coding harness by any definition. Fix: either add Zazen's tokens to the Codebuff row (tooltip note "includes Zazen fork") and add a ZCode row (proprietary desktop app, no repo found), or add a footnote "OpenRouter rows for forks and gateways (Zazen 8.3T, ZCode 1.3T, Strix 0.3T) are not shown."

6. **should-fix. The 85% claim is not the share of coding-agent traffic, only of BYOK traffic through one broker.** OpenRouter only sees requests with an app header routed through OpenRouter. Claude Code's 13.95T there is users overriding ANTHROPIC_BASE_URL (the sources file says so). Cursor's 0.9T excludes all its first-party traffic. Gemini CLI, Copilot CLI, Amp, Antigravity, Kiro, Devin never appear. A closed tool with a built-in model is structurally under-counted, so the metric is biased toward the open, model-agnostic side of the chart. Fix: change the callout second line to "They carry 85% of the 104.5T tokens routed through OpenRouter by these tools in 30 days. OpenRouter sees only bring-your-own-key traffic, so closed tools with bundled models are under-counted." and drop the implication that this is market share.

7. **should-fix. OpenCode first release month.** First GitHub release 0.0.45 is 2025-05-14 (https://api.github.com/repos/anomalyco/opencode/releases, oldest page). DATA says 2025-06 on the basis of a "public launch June 2025" blog post. Every other row uses first release or first preview, so use 2025-05 or footnote why launch month is used here.

8. **should-fix. Codebuff "Any model? vendor-locked" is wrong.** Freebuff/Codebuff lets users pick among many models and supports BYOK (https://freebuff.com/, https://github.com/CodebuffAI/freebuff). Its presence on OpenRouter at all comes from routing user-chosen models. Set `agnostic:true`.

9. **should-fix. Grok Build is a source dump, not an open project.** The repo is "a periodic export from xAI's internal monorepo, has no commit history, and explicitly does not accept external pull requests" (https://simonwillison.net/2026/Jul/15/grok-build/, https://appwrite.io/blog/post/grok-build-open-source). Apache-2.0 and BYO model are correct, so blue is defensible, but add a tooltip note "Source published 2026-07-15 as a snapshot; no history, no PRs." Also the row is dated 2026-05 (closed beta) while the code only became public 2026-07. For a chart about publishing code that gap deserves the note.

10. **should-fix. Zed and Warp stars are for an editor / terminal, not the agent.** Zed has 89,628 stars on a repo created 2021 for the whole editor; the agent panel dates from 2025-05. The sources file says "Stars are for the whole editor, not only the agent" but the tooltip does not. Add that note to both tooltips. Zed itself is correctly open: the agent runs locally in the GPL client, so no recolour needed.

11. **should-fix. Crush is FSL-1.1-MIT, not OSI open source.** Verified in LICENSE.md (https://github.com/charmbracelet/crush/blob/main/LICENSE.md). The legend says "Source code published", which is literally true, so blue is acceptable. But the title says "open" and a reader will equate blue with open source. Add "(source-available, MIT after 2 years)" to the tooltip license field or a footnote "Crush is source-available (FSL), not OSI open source."

12. **nit. "Issues-only repo" is loose for several rows.** Claude Code's repo holds plugins, a devcontainer, changelog and examples; Copilot CLI's holds install.sh and binaries; Kiro's holds its issue-triage automation (TypeScript scripts); Droid's is a 250MB docs repo. Kiro's README explicitly says "The Kiro product source code is not hosted here" (https://github.com/kirodotdev/Kiro). Change the tooltip string to "(no source in repo)" which is true for all eight proprietary rows with stars: Claude Code, Cursor, Kiro, Junie, Copilot CLI, Trae, Auggie, Droid.

13. **nit. Kimi Code CLI stars use the new repo only.** MoonshotAI/kimi-code has 7,213; the legacy kimi-cli repo that shipped the 2025-10 release has 11,307. Either sum them, use the legacy repo, or note "successor repo, legacy repo 11.3k" in the tooltip.

14. **nit. Footnote says "not in OpenRouter's top 200".** OpenRouter exposes 200 public rows but ranks run to 219 because private apps are hidden. Say "not among OpenRouter's 200 listed apps".

15. **nit. Duplicate OpenRouter entries are ignored.** Claude Code also appears at rank 179 (32.7B, via a gateway origin) and pi at rank 141 (49.9B, a community wrapper). OpenCode appears only via a gateway (rank 98, 79.7B), so its `null` is defensible but arguably 79.7B. Add a footnote "Only the vendor's own OpenRouter app is counted."

16. **nit. Granularity is inconsistent.** Devin and Devin Desktop are two rows from one maker, while Kiro IDE + CLI and Cursor IDE + CLI are one row each. Either merge Cognition into one row or split Cursor CLI (stable since Jan 2026, https://cursor.com/blog/cli). The scope note should say one row per product family.

17. **nit. Scope note is missing.** A critic will name Cursor CLI (covered by the Cursor row), Copilot coding agent (arguably covered by Copilot CLI), Jules, Codex cloud (covered by Codex row), Replit Agent, Lovable, Bolt, v0, Tabnine, Sourcegraph Cody (superseded by Amp), Manus. The app builders and cloud-only agents are reasonably out of scope, but nothing on the chart says so. Add a footnote: "Scope: agents a developer runs against their own repo (CLI, IDE, editor). App builders (Lovable, Bolt, v0, Replit) and hosted-only agents (Jules) excluded." If Hermes and OpenClaw stay, Manus and similar general agents need a stated reason for exclusion.

18. **nit. Title overclaims.** "The coding-agent harness layer is open" reads as a market statement. By count it is 26 of 39. By tokens it is 85% on a broker that under-counts closed tools (item 6) and 69% without the two general agents (item 1). By users the biggest closed tools (Cursor, Claude Code, Copilot) are not measured here at all. Safer: "Most coding-agent harnesses publish their code" or "Two in three coding-agent harnesses are open".

19. **nit. Cursor label may clip.** x domain starts 2023-01, Cursor sits at 2023-03 with a 33k-star bubble. Candidate labels to the left are rejected by `b.x0 < -margin.left + 4`, so it falls to a forced faint label. Start the domain at 2022-10 or allow the label to the right.

## Verified as correct

Stars: all 35 repos re-fetched, every value within 0 to 30 stars of DATA (natural drift). No forks, no mirrors. OpenRouter: Hermes Agent is rank 1 at 49.23T, and every token figure and rank for Claude Code, Kilo Code, Cline, pi, OpenClaw, omp, DeepSeek Harness, Codex, Cursor, Command Code, OpenHands, Zed, Zoo Code, Roo Code, goose, Codebuff, Qwen Code, Crush, Continue and Droid matches the live payload exactly. Release months confirmed: Cursor 2023-03, Aider 2023-05, Continue 2023-07, OpenHands 2024-03, Cline 2024-07, Roo Code 2024-11, Claude Code 2025-02, Kilo Code 2025-03, Codex CLI 2025-04, pi 2025-08, OpenClaw 2025-11 (v0.1.1 2025-11-25), omp 2026-01 (first release 2026-01-02), Hermes Agent 2026-02 (launch 2026-02-25), Zoo Code 2026-05 (v3.54.0 2026-05-16), Grok Build 2026-05 (beta), DeepSeek Harness 2026-08 (preview 2026-08-13). Roo Code archived 2026-05-15 confirmed via API `archived:true` and https://kilo.ai/compare/roo-code-shutdown-roomote. Devin Desktop rebrand 2026-06-02 confirmed. Licenses confirmed from repo LICENSE files for OpenClaw (MIT), Crush (FSL-1.1-MIT), Claude Code (all rights reserved), Warp (AGPL-3.0).

## Verdict

The numbers are clean. Every star count and every OpenRouter token figure reproduces from the live sources, and the release months hold up. What does not hold up is the story wrapped around them. The 85% figure is carried by Hermes Agent, a general-purpose agent, and collapses to 69% for coding tools alone. Warp is painted open when its agent runs in a closed cloud, which is exactly the objection the title invites. Two chart bugs (Droid drawn off the axis, Command Code in the wrong row) and one large missing bubble (Zazen, 8.25T) are easy fixes. Fix items 1 to 6 before publishing, soften the title, and this is a defensible chart.
